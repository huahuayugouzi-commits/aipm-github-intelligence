# AI 策略与事实边界

## 1. 为什么只在必要位置使用 AI

GitHub 元数据、快照差值和排行榜都是确定性问题，适合由程序完成。LLM 仅用于把 README 与仓库事实转化为产品视角分析，例如产品定位、目标用户、痛点、差异化和二次开发建议。这样既降低成本，也避免模型“计算”真实增长数据。

## 2. 输入与输出

模型输入包含仓库名称、URL、描述、Star、Fork、语言、活跃时间、Issue、License，以及截断后的 README。密钥只在服务端读取。

输出必须通过 Zod Schema，包含：

- 产品定位、目标用户、痛点与核心功能；
- AI 技术介入点、差异化、商业化潜力；
- AIPM 学习价值与二次开发可行性；
- `verifiedFacts`：可由 GitHub 证据支持的信息；
- `assumptions`：仍需用户研究或市场验证的判断；
- 来源 URL 与分析日期。

商业潜力必须标注 `verified` 或 `inference`，不得生成用户量、收入、合作或增长等无证据事实。

## 3. 何时重新分析

系统为每个项目计算分析指纹，综合 README 哈希、描述、License、Homepage、分类，以及 Star/Fork 的变化区间。只有项目首次进入或指纹发生重要变化时才重新分析。

缓存键同时包含模型名、Prompt 版本和 Schema 版本，避免在提示词或输出结构升级后误用旧结果。命中缓存也写入零 Token、零费用审计记录。

## 4. 预算控制

分析前先估算输入与输出 Token，并依次检查：

1. 每日 Token 上限；
2. 每周 Token 上限；
3. 单次任务 Token 上限；
4. 每日费用上限；
5. 每周费用上限。

模型价格由环境变量配置，费用按真实输入/输出 Token 分别估算，不硬编码厂商价格。预算不足时停止新的分析，但继续保存 GitHub 数据并生成可读周报。

## 5. 服务降级

以下情况会进入降级模式：缺少密钥、认证失败、余额或 Spend Limit、Rate Limit、超时、服务端错误、网络异常和 Schema 校验失败。

- 余额、认证、配置等不可通过重试解决的问题不重试。
- Rate Limit、超时、服务端和网络错误最多有限重试一次。
- 错误日志只保存安全错误码和用户可读消息，不保存 API Key 或完整上游响应。
- 前端继续展示最近一次历史分析，并提示“AI 分析服务暂时不可用”。

## 6. 当前适配范围

模型层兼容 OpenAI 风格的 `/chat/completions` API，可连接 OpenAI 或兼容服务。不同厂商对 `response_format` 的实现可能不同，上线前应使用“连接诊断”验证模型兼容性。

## 7. 后续优化

- 为分析 Schema 建立版本迁移与对比视图。
- 引入小规模人工评分集，评估事实忠实度、可操作性与一致性。
- 将 README 长文改为分段证据选择，进一步减少输入 Token。
- 对分析引用增加可定位的 README 证据片段。
