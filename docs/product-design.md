# 产品设计说明

## 1. 产品定位

AIPM GitHub Intelligence 是面向 AI 产品经理、转型候选人和需要跟踪开源生态的产品团队的情报工作台。它不是另一个只看累计 Star 的榜单，而是把“发现项目—验证数据—形成产品判断—沉淀历史报告”串成可持续工作流。

## 2. 核心用户与任务

| 用户 | 高频任务 | 当前痛点 | 产品响应 |
| --- | --- | --- | --- |
| AI 产品经理 | 每周发现值得研究的项目 | 搜索范围大、信息重复 | 七领域采集、去重、透明排序 |
| 转型候选人 | 找到可复刻的作品集题目 | 只看代码，不知道产品价值 | AIPM 产品分与结构化分析 |
| 小型产品团队 | 观察竞品和技术趋势 | 每周重复阅读同一 README | 快照、哈希缓存、历史周报 |

## 3. 核心业务流程

```text
GitHub REST API
  → 关键词采集与去重
  → SQLite 项目库与每日 Star 快照
  → 程序化排行榜
  → 变化检测与预算判断
  → AI 结构化分析（仅新增或重要变化）
  → 周报持久化
  → Dashboard / 排行榜 / 项目详情 / 历史周报
```

页面访问只读取数据库，不触发 GitHub 或模型 API。每周任务负责完整采集和报告生成；每日轻量任务只更新已收录项目的 Star、Fork、Issue 与活跃时间，用于形成真实增长基线。

## 4. 排行口径

- 综合热门榜：按当前累计 Star 排序，表达存量影响力。
- 本周热门榜：必须同时存在七天前与最新快照，按真实七日新增 Star 排序；历史不足时明确显示“积累中”。
- 近 30 天增长榜：由相隔约 30 天的本地快照计算，不用累计 Star 代替增长。
- 最近活跃榜：按 GitHub `pushed_at` 排序。
- AIPM 推荐榜：热度、活跃度、产品完整性、研究价值各占 25%，由程序计算。

“本周热门”还会排除纯 Awesome List、教程、课程、论文或 Prompt 合集，并要求 README 或描述呈现 App、Platform、Workflow、Deploy 等产品形态证据。

## 5. 关键产品决策

1. **数据事实与 AI 判断分层**：Star、License、更新时间来自 GitHub；目标用户、商业潜力等在页面中标为分析或推测。
2. **历史不足时不猜测**：首次运行宁可空榜，也不把累计 Star 冒充近期增长。
3. **低成本优先**：排名计算不用模型，页面刷新不调用模型，README 未变化时命中缓存。
4. **主体服务可降级**：模型不可用时，排行榜、GitHub 数据、历史周报和历史分析仍可浏览。
5. **可追溯**：每次任务记录触发方式、状态、采集量、Token、成本、错误与关联周报。

## 6. 页面结构

- Dashboard：系统状态、数据量、本周推荐、成本与最近任务。
- 排行榜：榜单口径说明、分类筛选、中文产品解读。
- 项目详情：GitHub 事实、历史快照、AI 分析、事实与推测边界。
- 情报周报：按生成时快照永久保存，支持 Markdown 导出。
- 运行记录：采集、分析、缓存命中、费用和错误追溯。
- 系统设置：只展示安全的配置状态与连接诊断，不回传密钥。

## 7. MVP 边界

当前版本聚焦单实例、单管理员、七类 AI 项目情报。暂不包含多用户账号、付费订阅、邮件推送、社区协作和复杂权限。SQLite 适合 MVP 与单副本部署；横向扩容前应迁移 PostgreSQL 并使用外部任务队列与分布式锁。

## 8. 下一步产品验证

- 访谈 5–8 位 AI 产品经理，验证周报是否减少筛选时间。
- 记录用户从榜单进入项目详情、再导出周报的转化路径。
- 建立人工标注集，评估“产品型仓库过滤”的准确率。
- 连续积累 30 天快照，验证增长榜稳定性与异常波动处理。
